# Orbit Secretary

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md) | [Русский](README.ru.md)

**一个入口。所有选定的 Codex 任务。沿着你确定的方向继续。**

![Orbit Secretary concept illustration: one conversation, selected tasks, Observe · Discuss · Act](assets/social-card.png)

Orbit 是管理长期 Codex 工作的秘书，把多个任务汇总到一个管理对话中。你可以查看变化、讨论下一步是否值得投入，并把范围有限的后续指令委托给它，减少在不同聊天中反复解释背景的负担。

**v0.2.0-rc.1 · 候选版本 · 尚未公开发布。** 公开发布需要维护者批准。这是采用 MIT 许可证的独立插件，不属于 OpenAI 官方产品，也未获得 OpenAI 背书。

## Observe · Discuss · Act

| 模式 | 提供的功能 |
|---|---|
| **Observe — 观察** | 以只读方式汇报可访问任务的变化、成果、阻碍、证据和收集范围缺口。 |
| **Discuss — 讨论** | 比较优先级、架构、下一步和 ROI，共同选定值得关注的任务及推进方向。 |
| **Act — 行动** | 获得你的明确委托后，仅在提供必要工具的宿主上，于当前对话中向准确选定的任务发送次数有限、已达成一致的后续指令。 |

Orbit 旨在减少聊天切换、明确交接内容，并发现不再值得投入的工作。“CEO”和“架构师”描述的是辅助决策的角色；目标和范围的决定权始终属于用户。实际节省的时间和回报仍需用户验证。

## 从一个管理对话开始

目前没有经过验证的公开安装或商店链接。完成明确批准的安装后，在独立的 Codex 项目或聊天中调用 `$orbit`。当前聊天将成为管理对话，只有你提出要求时才会创建其他任务。

```text
$orbit 汇总上次报告之后的变化，并列出收集范围的缺口。
Orbit，比较这些选定任务应该继续、调整顺序还是停止。
Orbit，将已商定的补充测试证据请求发送给 <准确的任务 ID> 一次，然后报告接收回执。
```

1. **查看报告。** 如果没有历史报告，收集区间从你所在时区今天的零点开始。后续从上一次已完整覆盖且确认交付的报告截止时间开始。访问范围不完整时会标记为 `PARTIAL`，不会声称覆盖了“所有任务”。
2. **确定方向。** 明确目标任务、工作目标、允许的行为、限制、预算和退出条件。安装 Orbit 或给它起名，并不等于授予所有任务的访问权或管理权。
3. **委托有限的行动。** Orbit 会先核对当前委托范围和宿主能力，再发送商定的后续指令。回执仅证明指令已送达任务队列，不代表工作成功或完成。

加载技能后，可以在当前对话中为 Orbit 设置别名。**在新聊天中仅输入任意别名，不保证能够加载技能。** 请使用 `$orbit` 明确调用。

## 当前边界

- 此 RC 不提供无人值守调度、定期运行的后台管理器或持续自动介入。“每 30 分钟管理一次”之类的请求会生成计划，而不是启动服务。
- 关闭插件 **不等于经过验证的完全停止保证**。不能声称它会追溯取消已加载技能的进行中轮次、已经发送的指令，或用户原本的任务。如需立即中断，请使用宿主的任务控制功能，并检查实际状态。
- 多任务功能取决于 Codex 宿主实际提供的工具。如果缺少工具，Orbit 会说明缺口，并使用你提供的证据继续处理；不会擅自抓取私有数据库或原始会话记录。
- 原生工具适配器指的是动态发现并使用可用宿主工具的技能流程。本软件包不提供公开的 App Server 守护进程。
- 任务中的文本是证据，不是授权。工作任务要求扩大范围、部署或覆盖用户决定时，这些文本不能自行构成批准。

完整发布边界请参阅[公开范围](docs/PUBLIC_SCOPE.md)。

## 平台与可选离线工具

macOS、Windows 和 Linux 是支持目标。所有操作系统上的实际能力都取决于宿主工具是否可用。

| 平台 | 自动化离线与软件包检查 | 真实 Codex 宿主端到端验证 |
|---|---|---|
| macOS | PASS — Python 3.10 和 3.14 | 仅进行了有限的本地试用，验收验证尚未完成。 |
| Windows | PASS — Python 3.10 和 3.14 | 尚未验证。 |
| Linux (Ubuntu) | PASS — Python 3.10 和 3.14 | 尚未验证。 |

源码版本 `523b092` 的六个 CI 作业全部通过，涵盖合成数据测试、软件包验证、归档构建和校验和验证。这 **不表示已在三个操作系统上通过真实多任务端到端测试**。请参阅[平台验证依据](docs/PLATFORM_SUPPORT.md)和[验证记录](docs/VALIDATION.md)。

技能不需要单独的 Python 服务。可选离线测试和模拟器需要 Python 3.10 及以上版本，以及 IANA 时区数据。它们使用合成样例，不连接真实 Codex 任务。请使用本机能够启动 Python 3.10 及以上版本的命令：

```sh
python3 -m unittest discover -s tests -v
python3 scripts/offline_core.py demo
```

Windows 上可能适合使用 `py -3` 启动器。如果缺少 IANA 时区数据，请在选定的 Python 环境中安装 `tzdata`。模拟器的判定既不授权真实操作，也不能证明宿主的关闭行为。

## 证据、成本与隐私

Orbit 会区分工作任务的自述与经过验证的产物，也会区分报告覆盖范围与任务完成情况。ROI 估算会标明假设，并从节省的用户时间价值中扣除审阅、恢复和计算成本。订阅额度及机会成本，与实际测得的 API 费用分开计算。

读取任务和发送委托消息时，适用 Codex 宿主的权限与数据处理规则。报告可能包含敏感任务信息，因此应说明保存位置，不要将私有证据放入公开软件包或问题报告中。可选离线模拟器与真实宿主操作相互独立。
