# Orbit Secretary (궤도 조정자)

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md) | [Русский](README.ru.md)

**多个 Codex 任务。一个对话。你确定的方向。**

> 当无数任务沿着各自的轨道运行时，有这样一个存在：观察、判断、调整轨道，帮助它们避免碰撞。

![Orbit Secretary：在一个对话中观察、讨论和协调选定任务的秘书](assets/social-card.png)

Orbit 是为同时开展多个长期 Codex 任务的人准备的秘书。你可以在一个对话中接收简报、决定哪些工作值得关注，再让 Orbit 把你的方向传达给选定的任务。

## Orbit 能帮你做什么

- **在一处了解进展。** 不用逐个打开对话，就能知道发生了什么变化、哪些工作已完成、哪些事项需要你决定。
- **决定把时间用在哪里。** 比较优先级、前置工作，以及剩余投入与预期收益。
- **把决定落实到工作中。** 先设定时间和后续指令的次数上限，再委托 Orbit 向选定任务发送已商定的指令。

## Observe · Discuss · Act

| 模式 | 可以委托的内容 |
|---|---|
| **Observe — 获取简报** | 汇总进度、结果、阻碍和未能确认的内容。仅要求读取和汇报，不会向你的任务发送指令。 |
| **Discuss — 确定方向** | 比较下一步、架构选择，以及是否值得继续投入。由你决定协调哪些任务、如何协调。 |
| **Act — 协调选定任务** | 发送你委托的后续指令，然后报告接收情况和任务实际确认的结果。 |

## 开始使用

安装 Orbit 后，打开你希望接收简报的 Codex 对话或项目，在那里调用 `$orbit`：

```text
$orbit 汇总今天的工作，以及需要我关注和决定的事项。
```

接着自然地继续对话即可：

```text
Orbit，这些任务中我应该先看哪个？为什么？
Orbit，比较继续这个任务和缩小它的范围。
Orbit，请向刚才选定的任务发送一次指令，让它整理尚待决定的事项。
```

1. **查看简报。** 第一份报告从你所在时区今天的零点开始。后续报告以上一次已确认的报告为起点。Orbit 会告诉你哪些信息未能收集。
2. **选择要协调的工作。** 从简报中选择任务，或说出目标任务的名称。Orbit 会在发送任何内容前确认目标。
3. **确定委托范围。** 商定目标、允许的指令、时间限制和后续指令次数。Orbit 会在当前对话中按这个范围执行协调，并报告结果。

你也可以只用 Orbit 获取简报和讨论方向。是否委托后续指令，由你选择。

## 用你喜欢的名字称呼它

调用 `$orbit` 后，可以为 Orbit 设置一个在当前对话中使用的别名。开启新对话时，请先再次调用 `$orbit`，然后再使用别名。

## 使用时需要了解的事

- **范围由你决定。** Orbit 只协调你选定的任务；必须由你亲自作出的决定和批准，仍由你处理。
- **协调在当前对话中进行。** 不包含无人值守、周期性运行的后台管理。
- **关闭插件不会撤回已经发出的工作。** 已送达的指令和正在运行的任务不会自动取消。如需停止正在运行的任务，请使用 Codex 的任务控制功能。
- **可用功能取决于你的 Codex 环境。** 读取和协调其他任务，需要 Codex 提供相应工具。如果某项功能不可用，Orbit 会说明限制，也可以使用你提供的材料来协助整理。
- **指令已发送不等于任务已完成。** Orbit 会分别报告送达情况、任务的回复和已确认的结果，并明确指出缺失的信息。

关于报告和委托方式，请参阅[功能详情](docs/PUBLIC_SCOPE.md)。

## 使用环境、费用与隐私

Orbit 面向 **macOS、Windows 和 Linux 上的 Codex 环境**。无需设置单独的服务，直接在 Codex 中使用即可。

简报和后续指令会使用你的 Codex 使用额度。讨论 ROI 时会明确说明假设，并考虑协调本身所需的时间和成本。

Orbit 没有由发布者单独运营的后端或使用信息收集服务。任务内容通过 Codex 和你配置的模型处理；报告保留在对话中，或保存在你选择的工作区。
