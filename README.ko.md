# Orbit Secretary (궤도 조정자)

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md) | [Русский](README.ru.md)

**여러 Codex 작업을 한 대화에서, 내가 정한 방향으로.**

> 수많은 작업이 각자의 궤도를 돌고 있을 때, 충돌하지 않도록 바라보고 판단하며 궤도를 조정하는 존재.

![Orbit Secretary: 한 대화에서 선택한 작업을 관측하고 논의하며 조율하는 비서](assets/social-card.png)

Orbit은 여러 장기 작업을 진행하는 사람을 위한 Codex 비서입니다. 한 대화에서 핵심을 짧게 보고받고, 어디에 관심을 기울일지 판단하고, 선택한 작업에 내 방향을 전달하는 일을 맡길 수 있습니다.

## Orbit으로 할 수 있는 일

- **여러 작업의 상황을 한눈에 파악합니다.** 대화를 하나씩 열지 않고 무엇이 달라졌고, 무엇이 끝났고, 어떤 결정이 필요한지 확인합니다.
- **지금 시간을 쓸 곳을 정합니다.** 우선순위와 선행 작업, 남은 노력 대비 기대 효과를 함께 비교합니다.
- **정한 방향을 작업에 전달합니다.** 시간과 횟수 제한을 정하고, 선택한 작업에 합의한 후속 지시를 보내는 일을 위임합니다.

## Observe · Discuss · Act

| 모드 | 맡길 수 있는 일 |
|---|---|
| **Observe — 보고받기** | 진행 상황과 주요 문제, 사용자가 결정할 일을 먼저 짧게 정리합니다. 중요한 실패와 불확실성도 함께 알립니다. 조회와 보고만 요청하면 다른 작업에 지시를 보내지 않습니다. |
| **Discuss — 방향 정하기** | 다음 단계, 아키텍처 선택, 더 투자할 가치가 있는지를 비교합니다. 어떤 작업을 어느 방향으로 조율할지는 사용자가 정합니다. |
| **Act — 선택한 작업 조율하기** | 위임한 지시를 전달한 뒤 접수·시작·아직 확인되지 않음 중 확인 가능한 상태를 짧게 알리고, 완료를 기다리지 않고 사용자에게 돌아옵니다. |

필요할 때 세부 내용, 근거, 확인 가능한 전체 작업 목록을 요청하세요. 한 번 자세한 답변을 요청해도 이후 답변은 기본적으로 짧게 유지합니다.

## 시작하기

Orbit을 설치한 뒤 보고를 받을 Codex 대화나 프로젝트를 열고 `$orbit`를 호출하세요.

```text
$orbit 오늘 진행한 작업들과 내가 결정해야 할 내용을 정리해줘.
```

이후에는 자연스럽게 대화를 이어 가면 됩니다.

```text
오르빗, 이 작업들 중 지금 먼저 살펴볼 것은 뭐고, 이유는 뭐야?
오르빗, 이 작업을 계속하는 것과 범위를 줄이는 것을 비교해줘.
오르빗, 방금 선택한 작업에 남은 결정사항을 정리해달라는 지시를 한 번 보내줘.
```

1. **보고를 확인합니다.** 첫 보고는 내 시간대의 오늘 0시부터 시작하고, 이후에는 확인된 이전 보고를 기준으로 변경 사항을 정리합니다. 수집하지 못한 내용은 함께 알려줍니다.
2. **조율할 작업을 고릅니다.** 보고에서 작업을 선택하거나 작업 이름을 말하세요. Orbit이 대상을 확인한 뒤 진행합니다.
3. **맡길 범위를 정합니다.** 목표, 허용할 지시, 시간과 횟수를 정하면 Orbit이 현재 대화에서 지시를 넘기고, 전달 상태를 짧게 알린 뒤 사용자에게 돌아옵니다.

보고와 논의만 이용해도 됩니다. 후속 지시를 맡길지는 필요할 때 선택하세요.

**Orbit이 작업을 직접 수행하나요?**

간단한 답변, 현황, 우선순위와 전달 상태 안내는 Orbit이 직접 맡습니다. 벤치마크와 **예상 1분 이상** 걸리는 일은 보통 다른 작업자에게 위임합니다. **예상 10분 이상** 걸리는 일은 위임하며, 허용된 위임 방법이 없으면 긴 작업을 직접 시작하는 대신 인계 내용을 준비하고 부족한 점을 설명합니다.

예상 1분 이상 10분 미만의 일을 불가피하게 직접 맡을 때는 이유와 범위를 짧게 알립니다. 이후 사용자가 특정 작업을 직접 하라고 명시하면 그 요청을 우선합니다. 1분·10분은 예상 작업량 기준이며 타이머나 예약 주기가 아닙니다. 사용자 작업 목록에 새 작업을 만드는 것은 명시적으로 요청했을 때뿐입니다.

## 원하는 이름으로 부르기

`$orbit`를 호출한 뒤에는 해당 대화에서 사용할 별칭을 정할 수 있습니다. 새 대화에서는 `$orbit`로 먼저 불러온 뒤 별칭을 사용하세요.

## 사용 전에 알아둘 점

- **조율 범위는 사용자가 정합니다.** 선택한 작업을 대상으로 움직이며, 사용자가 직접 내려야 할 결정이나 승인을 대신하지 않습니다.
- **조율은 현재 대화에서 진행됩니다.** 자리를 비운 동안 정해진 주기마다 자동으로 개입하는 백그라운드 관리 기능은 제공하지 않습니다.
- **플러그인을 꺼도 이미 전달한 일은 되돌려지지 않습니다.** 전송한 지시나 진행 중인 작업이 자동으로 취소되지는 않습니다. 실행 중인 작업을 멈추려면 Codex의 작업 제어 기능을 사용하세요.
- **사용하는 Codex 환경에 따라 이용 가능한 기능이 달라집니다.** 다른 작업을 조회하고 조율하려면 Codex에서 해당 기능을 제공해야 합니다. 이용할 수 없는 기능은 Orbit이 안내하며, 직접 제공한 자료를 바탕으로 정리를 도울 수도 있습니다.
- **지시 전달과 작업 완료를 구분합니다.** 접수 여부, 작업의 응답, 확인된 결과를 나누어 보고하며 확인되지 않은 내용도 알려줍니다.

보고와 위임 방식은 [기능 상세](docs/PUBLIC_SCOPE.md)에서 더 살펴볼 수 있습니다.

## 사용 환경·비용·개인정보

Orbit은 **macOS·Windows·Linux의 Codex 환경**을 대상으로 합니다. 별도 서비스를 설정하지 않고 Codex 안에서 사용합니다.

보고와 후속 지시에는 Codex 사용량이 소모됩니다. ROI를 논의할 때는 가정을 밝히고 조율 자체에 드는 시간과 비용도 함께 고려합니다.

Orbit은 별도 운영 서버나 사용 정보 수집 서비스를 두지 않습니다. 작업 내용은 Codex와 설정된 모델을 통해 처리되며, 보고서는 현재 대화 또는 사용자가 정한 작업 공간에 남습니다.
