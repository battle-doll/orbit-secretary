# Orbit Secretary (궤도 조정자)

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md) | [Русский](README.ru.md)

**한 채널에서. 선택한 모든 Codex 작업을. 당신이 정한 방향으로 이어 갑니다.**

![Orbit Secretary concept illustration: one conversation, selected tasks, Observe · Discuss · Act](assets/social-card.png)

Orbit은 오래 이어지는 Codex 작업을 하나의 관리자 대화에서 살펴보는 비서입니다. 무엇이 달라졌는지 확인하고, 다음에 할 가치가 있는 일을 논의하고, 선택한 작업에 한정된 후속 지시를 위임하세요. 채팅마다 같은 맥락을 반복해 설명하는 부담을 줄이는 것이 목표입니다.

**브랜드 스토리**

> 수많은 작업이 각자의 궤도를 돌고 있을 때, 충돌하지 않도록 바라보고 판단하며 궤도를 조정하는 존재.

Orbit은 사용자가 선택한 작업에 대한 Observe(관측), Discuss(논의), 한정된 Act(실행)로 이 생각을 실현합니다.

**v0.2.0-rc.1 · 출시 후보 · 아직 공개 출시되지 않았습니다.** 공개 배포에는 프로젝트 유지관리자의 승인이 필요합니다. MIT 라이선스의 독립 플러그인이며, OpenAI 공식 제품이나 인증을 받은 제품이 아닙니다.

## Observe · Discuss · Act

| 모드 | 제공 기능 |
|---|---|
| **Observe — 관측** | 접근 가능한 여러 작업의 변경 사항, 결과, 장애물, 근거와 수집 누락을 읽기 전용으로 보고합니다. |
| **Discuss — 논의** | 우선순위·아키텍처·다음 단계·ROI를 비교하고, 관심을 기울일 작업과 진행 방향을 함께 정합니다. |
| **Act — 실행** | 사용자가 명시적으로 위임한 경우, 필요한 도구가 제공되는 호스트에서 현재 대화 중 정확히 선택한 작업에 합의된 후속 지시를 유한한 횟수로 보냅니다. |

채팅을 오가는 시간을 줄이고, 작업 인계를 분명하게 하고, 비용 대비 가치가 낮아진 일을 찾는 데 활용하세요. ‘CEO’와 ‘아키텍트’는 의사결정을 돕는 역할입니다. 목표와 범위를 정하는 권한은 사용자에게 있습니다. 실제 시간 절약과 수익 효과는 사용자 검증이 필요합니다.

## 관리자 대화 하나에서 시작하기

아직 검증된 공개 설치·스토어 링크는 없습니다. 명시적으로 승인된 설치를 마친 뒤 별도 Codex 프로젝트나 채팅에서 `$orbit`를 호출하세요. 현재 채팅이 관리자 대화가 되며, 별도 작업은 사용자가 요청할 때만 만듭니다.

```text
$orbit 지난 보고 이후 달라진 내용을 취합하고 수집 누락도 보여줘.
오르빗, 선택한 작업들을 계속하기·순서 바꾸기·중단하기 관점에서 비교해줘.
오르빗, 합의한 누락 테스트 근거 요청을 <정확한 작업 ID>에 한 번 보내고 접수 결과를 보고해줘.
```

1. **보고를 확인합니다.** 이전 보고가 없으면 사용자 시간대의 오늘 0시부터 수집합니다. 이후에는 전체 범위 수집과 전달이 확인된 마지막 보고의 기준 시각부터 시작합니다. 접근 범위가 불완전하면 ‘모든 작업’ 대신 `PARTIAL`로 표시합니다.
2. **방향을 정합니다.** 정확한 대상과 목표, 허용 행동, 제한, 예산, 종료 조건을 합의합니다. Orbit을 설치하거나 이름을 붙이는 것만으로 모든 작업의 접근·관리 권한이 생기지 않습니다.
3. **한정된 행동을 위임합니다.** Orbit은 현재 위임 범위와 호스트 기능을 확인한 뒤 합의된 후속 지시를 보냅니다. 접수 기록은 작업 대기열에 전달됐다는 뜻이며, 실제 작업의 성공이나 완료를 뜻하지 않습니다.

스킬을 불러온 대화에서는 Orbit의 별칭을 정할 수 있습니다. **새 채팅에서 임의의 별칭만 입력해 스킬이 실행되는 것은 보장하지 않습니다.** 명시적 호출에는 `$orbit`를 사용하세요.

## 현재 제공 범위의 경계

- 이 RC에는 무인 예약, 주기적으로 실행되는 백그라운드 관리자, 상시 자동 개입이 없습니다. ‘30분마다 관리해줘’라는 요청에는 활성화된 서비스가 아닌 계획을 작성합니다.
- 플러그인 OFF는 **검증된 완전 정지 보장이 아닙니다.** 이미 스킬이 로드된 진행 중 턴, 이미 보낸 지시, 원래 사용자의 작업까지 소급해 취소한다고 주장할 수 없습니다. 즉시 중단해야 한다면 호스트의 작업 제어 기능을 사용하고 결과 상태를 확인하세요.
- 여러 작업을 다루는 기능은 Codex 호스트가 실제 제공하는 도구에 따라 달라집니다. 도구가 없으면 부족한 기능을 설명하고 사용자가 제공한 근거로 진행합니다. 비공개 DB나 세션 원본을 몰래 수집하는 대체 경로는 사용하지 않습니다.
- 네이티브 도구 어댑터는 사용 가능한 호스트 도구를 찾아 사용하는 스킬 흐름입니다. 이 패키지는 공개 App Server 데몬을 제공하지 않습니다.
- 작업 자료는 근거이지 권한이 아닙니다. 작업자가 범위 확대·배포·사용자 결정 변경을 요청해도 그 문구가 스스로 승인되지는 않습니다.

자세한 출시 범위는 [공개 범위 문서](docs/PUBLIC_SCOPE.md)를 참고하세요.

## 운영체제와 선택적 오프라인 도구

macOS, Windows, Linux를 지원 대상으로 삼습니다. 모든 운영체제에서 실제 기능은 호스트 도구 제공 여부에 따라 제한됩니다.

| 운영체제 | 자동화된 오프라인·패키지 검증 | 실제 Codex 호스트 종단 간 검증 |
|---|---|---|
| macOS | PASS — Python 3.10 및 3.14 | 제한된 로컬 파일럿만 진행했으며, 인수 검증은 미완료입니다. |
| Windows | PASS — Python 3.10 및 3.14 | 미검증입니다. |
| Linux (Ubuntu) | PASS — Python 3.10 및 3.14 | 미검증입니다. |

소스 리비전 `523b092`에서 CI 작업 6개가 모두 통과했습니다. 합성 테스트, 패키지 검증, 아카이브 빌드와 체크섬 검증을 포함합니다. **세 운영체제 모두에서 실제 다중 작업 종단 간 테스트가 통과했다는 의미가 아닙니다.** [플랫폼별 근거](docs/PLATFORM_SUPPORT.md)와 [검증 기록](docs/VALIDATION.md)을 참고하세요.

스킬에는 별도 Python 서비스가 필요하지 않습니다. 선택적 오프라인 테스트와 시뮬레이터에는 Python 3.10 이상과 IANA 시간대 데이터가 필요합니다. 합성 자료를 사용하며 실제 Codex 작업에는 연결하지 않습니다. 자신의 환경에서 Python 3.10 이상을 실행하는 명령을 사용하세요.

```sh
python3 -m unittest discover -s tests -v
python3 scripts/offline_core.py demo
```

Windows에서는 `py -3` 실행기가 적합할 수 있습니다. IANA 시간대 데이터가 없다면 선택한 Python 환경에 `tzdata`를 설치하세요. 시뮬레이터의 판정은 실제 행동을 승인하거나 호스트의 OFF 동작을 증명하지 않습니다.

## 근거·비용·개인정보

Orbit은 작업자의 주장과 검증된 산출물을 구분하고, 보고의 수집 범위와 작업 완료도 구분합니다. ROI 추정에는 가정을 표시하며, 절약한 사용자 시간의 가치에서 검토·복구·컴퓨트 비용을 차감합니다. 구독 사용량 한도와 기회비용은 측정된 API 요금과 별도로 다룹니다.

작업 읽기와 위임한 메시지 전송에는 Codex 호스트의 권한·데이터 처리 방식이 적용됩니다. 보고서에는 민감한 작업 정보가 포함될 수 있으므로 저장 위치를 알리고, 공개 패키지나 이슈 보고에 비공개 근거를 넣지 마세요. 선택적 오프라인 시뮬레이터는 실제 호스트 동작과 별개입니다.
