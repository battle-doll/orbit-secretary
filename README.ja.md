# Orbit Secretary (궤도 조정자)

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md) | [Русский](README.ru.md)

**ひとつの窓口で。選んだすべての Codex タスクを。あなたが決めた方向へ。**

![Orbit Secretary concept illustration: one conversation, selected tasks, Observe · Discuss · Act](assets/social-card.png)

Orbit は、長期にわたる Codex の作業をひとつの管理用会話にまとめる秘書です。変更点を確認し、次に取り組む価値のあることを話し合い、選んだタスクへの範囲を限定した追加指示を委任できます。チャットごとに同じ背景を説明する負担を減らすことを目指します。

**ブランドストーリー**

> 無数のタスクがそれぞれの軌道を巡るとき、互いに衝突しないよう見守り、判断し、軌道を調整する存在。

Orbit は、ユーザーが選んだタスクへの Observe（観測）、Discuss（検討）、回数と範囲を限定した Act（実行）で、この考えを形にします。

**v0.2.0-rc.1 · リリース候補 · まだ一般公開されていません。** 公開にはメンテナーの承認が必要です。MIT ライセンスの独立したプラグインであり、OpenAI の公式製品でも、同社の認定を受けた製品でもありません。

## Observe · Discuss · Act

| モード | 提供する機能 |
|---|---|
| **Observe — 観測** | アクセス可能な複数タスクの変更、成果、障害、根拠、収集範囲の不足を読み取り専用で報告します。 |
| **Discuss — 検討** | 優先順位、アーキテクチャ、次の手順、ROI を比較し、注力するタスクと進む方向を一緒に決めます。 |
| **Act — 実行** | ユーザーが明示的に委任した場合、必要なツールを提供するホスト上で、現在の会話中に、正確に指定されたタスクへ合意済みの追加指示を有限回送ります。 |

チャットの行き来を減らし、引き継ぎを明確にし、費用に見合わなくなった作業を見つけるために使えます。「CEO」「アーキテクト」は意思決定を支援する役割を表します。目標と範囲を決める権限はユーザーにあります。実際の時間短縮やリターンは、ユーザーによる検証が必要です。

## ひとつの管理用会話から始める

確認済みの公開インストール先やストアへのリンクはまだありません。明示的に承認したインストールの後、別の Codex プロジェクトまたはチャットで `$orbit` を呼び出してください。現在のチャットが管理用会話となり、新しいタスクを作るのはユーザーが依頼した場合だけです。

```text
$orbit 前回の報告以降の変更をまとめ、収集できていない範囲も示して。
Orbit、選んだタスクについて、継続・順序変更・中止を比較して。
Orbit、合意した不足テスト根拠の提出依頼を <正確なタスク ID> に一度送り、受付結果を報告して。
```

1. **報告を確認する。** 過去の報告がなければ、ユーザーのタイムゾーンの今日 0 時から収集します。以後は、対象範囲の収集と報告の受け渡しが確認された前回の基準時刻から始めます。アクセス範囲が不完全な場合は「すべてのタスク」ではなく `PARTIAL` と表示します。
2. **方向を決める。** 正確な対象、目標、許可する行動、制限、予算、終了条件を合意します。インストールや名前の設定だけで、すべての作業へのアクセス権や管理権限が与えられることはありません。
3. **限定した行動を委任する。** Orbit は現在の委任範囲とホストの機能を確認してから、合意済みの追加指示を送ります。受付記録が示すのはタスクのキューへの送信であり、作業の成功や完了ではありません。

スキルを読み込んだ会話では Orbit に別名を付けられます。**新しいチャットで任意の別名だけを入力してスキルが起動することは保証されません。** 明示的な呼び出しには `$orbit` を使ってください。

## 現在の制限

- この RC は、無人スケジュール、定期実行するバックグラウンド管理者、常時の自動介入を提供しません。「30 分ごとに管理して」という依頼には計画を作成し、サービスを有効化したとは表示しません。
- プラグインの OFF は、**検証済みの完全停止を保証するものではありません。** すでに読み込まれた実行中のターン、送信済みの指示、元のユーザータスクまで遡って取り消せるとは主張できません。即時停止が必要な場合はホストのタスク制御を使い、結果の状態を確認してください。
- 複数タスクの操作は Codex ホストが実際に提供するツールに依存します。ツールがない場合は不足を説明し、ユーザーが提供する根拠で進めます。非公開データベースやセッション原本を無断で収集する代替経路は使いません。
- ネイティブツールアダプターとは、利用可能なホストツールを検出して使うスキルの手順です。このパッケージは公開 App Server デーモンを提供しません。
- タスク内の文章は根拠であり、権限ではありません。作業者が範囲拡大、デプロイ、ユーザーの決定変更を求めても、その文章が自ら承認になることはありません。

詳細は[公開範囲](docs/PUBLIC_SCOPE.md)を参照してください。

## OS と任意のオフラインツール

macOS、Windows、Linux をサポート対象としています。どの OS でも、実際の機能はホストのツール提供状況に左右されます。

| OS | 自動化されたオフライン・パッケージ検証 | 実際の Codex ホストの E2E 検証 |
|---|---|---|
| macOS | PASS — Python 3.10 および 3.14 | 限定的なローカル試行のみで、受け入れ検証は未完了です。 |
| Windows | PASS — Python 3.10 および 3.14 | 未検証です。 |
| Linux (Ubuntu) | PASS — Python 3.10 および 3.14 | 未検証です。 |

ソースリビジョン `523b092` で CI ジョブ 6 件すべてが合格しました。合成データのテスト、パッケージ検証、アーカイブのビルド、チェックサム検証を含みます。**3 つの OS すべてで実際の複数タスクのエンドツーエンドテストに合格したという意味ではありません。** [プラットフォーム別の根拠](docs/PLATFORM_SUPPORT.md)と[検証記録](docs/VALIDATION.md)を参照してください。

スキルに別途 Python サービスは不要です。任意のオフラインテストとシミュレーターには Python 3.10 以上と IANA タイムゾーンデータが必要です。合成データを使用し、実際の Codex タスクには接続しません。ご利用の環境で Python 3.10 以上を選択するコマンドを使ってください。

```sh
python3 -m unittest discover -s tests -v
python3 scripts/offline_core.py demo
```

Windows では `py -3` が適切なランチャーの場合があります。IANA タイムゾーンデータがなければ、選んだ Python 環境に `tzdata` をインストールしてください。シミュレーターの判定は、実際の行動を承認したり、ホストの OFF 動作を証明したりするものではありません。

## 根拠・費用・プライバシー

Orbit は作業者の主張と検証済みの成果物を区別し、報告の収集範囲とタスクの完了も区別します。ROI の見積もりでは仮定を明示し、節約したユーザー時間の価値からレビュー、復旧、計算処理の費用を差し引きます。サブスクリプションの利用枠と機会費用は、実測した API 料金と分けて扱います。

タスクの読み取りと委任されたメッセージの送信には、Codex ホストの権限とデータ処理方針が適用されます。報告には機密情報が含まれる可能性があるため、保存先を明示し、公開パッケージや問題報告に非公開の根拠を含めないでください。任意のオフラインシミュレーターは、実際のホスト操作とは別のものです。
